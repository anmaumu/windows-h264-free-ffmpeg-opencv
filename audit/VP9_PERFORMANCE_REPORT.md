# VP9デコード性能比較

## 結論

今回のWindows x64環境、320×240・30 fps・120フレームのVP9/MKV素材では、自作FFmpeg＋自作OpenCVと公式 `opencv-python-headless` の性能は実質同等だった。自作版の明確な性能低下は観測されていない。

## 比較条件

| 項目 | 自作版 | 標準版 |
|---|---|---|
| OpenCV | 4.10.0 自作 | `opencv-python-headless==4.10.0.84` |
| Python | 3.12 | 3.12 |
| NumPy | 1.26.4 | 1.26.4 |
| FFmpeg API | avcodec 60.31.102 | avcodec 58.134.100 |
| 入力 | 同じ `audit/media/vp9.mkv` | 同左 |
| バックエンド | `CAP_FFMPEG` | `CAP_FFMPEG` |
| ウォームアップ | 5回 | 5回 |
| 本測定 | 100回、合計12,000フレーム | 同左 |

入力SHA-256は `f8ba0754531f0ec7710753dfb387cd0682cd98e4983c0fd0d94cb8db2549d8d4`。各フレームは `(240, 320, 3)` の有効なBGR画像であることを確認した。

## 結果

| 指標 | 自作版 | 標準版 | 自作版÷標準版 |
|---|---:|---:|---:|
| 1動画あたり時間の中央値から算出したFPS | 1,325.38 | 1,326.38 | 99.925% |
| 全測定時間から算出したFPS | 1,315.19 | 1,321.67 | 99.509% |
| 最短処理時間 | 0.07814秒 | 0.07756秒 | — |
| 最長処理時間 | 0.11885秒 | 0.10755秒 | — |

中央値差は約0.075%、全測定の差は約0.49%であり、通常の測定揺らぎを考えると実質同等と判断する。

## 注意点

自作FFmpegは `--disable-x86asm` で構成されている。このテストでは低下が現れなかったが、4K、高ビットレート、10-bit VP9などデコード負荷が高い素材でも同等とは断定できない。また、標準版と自作版はいずれもこの測定ではOpenCV経由のソフトウェアデコードであり、ハードウェアデコードの比較ではない。

生データは `audit/logs/benchmark-custom-vp9.json` と `audit/logs/benchmark-standard-vp9.json` にあり、全100回の所要時間、OpenCVビルド情報、検証結果を含む。再実行用プログラムは `audit/scripts/benchmark_opencv_vp9.py`。
